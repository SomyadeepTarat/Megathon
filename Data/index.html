Illustrative simulation informed by published statistics. These records are not observed homes, transaction prices or measured energy readings.

Dataset version: kew_london_v3 · Reviewed: 11 October 2026

This README documents every field in the property, energy and emission-factor CSVs, how labels and derived values are generated, and the evidence supporting the reported results. The property schema has 51 columns, energy has 13, and emission factors have 10. Column names, order, API contracts and ML input features are unchanged. This documentation does not modify the data or models.

Current application integration: the merged application now defaults to the 1,900 fresh London simulations, excluding the original hundred from its active London repository. Run scripts/prepare_london_demo.py for the active data/model. See the London integration review, workflow evidence, and current setup instructions. The generation/evaluation results below describe the original frozen data review; integration reproduction is not a new independent test or evidence of observed market accuracy.

The 2,000-property dataset comprises 100 retained synthetic legacy properties and 1,900 newly simulated London properties, with 24,000 monthly energy rows for January–December 2025. The original hundred include multiple regions; the new cohort is entirely Greater London. No property or meter row is an observed household record. Published reference statistics and emission factors are distinct from the synthetic property-level records they inform.

3. Notation, units and missing-value conventions #

  • A: floor area in m2; a: scenario property age in years; b: bedrooms.
  • o = min(5, max(1, b)): assumed occupants, not observed household occupancy.
  • H_m, W_m: delivered space heat/hot water in month m, kWh.
  • B_m: base appliance electricity; D_m: total electrical demand, kWh.
  • G_m: purchased gas; I_m: purchased/grid electricity, kWh.
  • V_m: PV generation; S_m: PV self-consumption; X_m: PV export, kWh.
  • eta: boiler efficiency; c_s: space-heating COP; c_w: hot-water COP.
  • k_h, k_e: pilot-calibrated space-heat and appliance multipliers.
  • sum_m: sum of the twelve calendar months; clip(x,l,u)=max(l,min(u,x)).
  • N(mu,sigma): normal draw with standard deviation sigma; U(l,u): uniform draw.

CSV numbers are stored as text. Purchased monthly gas/grid values are formatted to 2 decimal places; monthly and annual physical kWh components to 6; renewable share to 9; floor area to 1; generated prices to the nearest GBP 1,000. Python round() and formatting semantics are used, including nearest-even ties. Several annual fields sum already rounded monthly physical values, so formula identities are verified with explicit rounding tolerances, not exact float equality.

Blank compatibility flags mean unknown, not false. Blank efficiencies/COPs mean not applicable to that heating system in this complete main simulation. Genuine modelled zero gas for electric homes is 0, distinct from a missing reading. Missing/incomplete annual readings remain unavailable; they are not imputed as zero. False feasibility in QA fixtures is an explicit synthetic test condition, not survey evidence. solar does not imply roof suitability.

4. Property generation and label formulas #

4.1 Stable random streams and identity #

For the 1,900 new rows, i=0..1899:

Formula / definition
property_id = 'P' + six-digit(100001 + i)
customer_id = replace first 'P' with 'C'
seed(channel,id) = integer(SHA256('20261011:' + channel + ':' + id), base 16)
channel = 'physical' or 'price'

Each stream uses Python random.Random. Pricing uses a separate stream; changing the EPC letter alone cannot create a price premium. Physical and price values still share area, bedroom and age characteristics; statistical correlation is not causal evidence. The stable ID scheme prevents reuse of previously exposed v2 IDs. Increasing the total preserves the existing generated prefix with the same runtime/reference snapshot. A separate fixed pilot uses PILOT00000– PILOT02999, disjoint from every development/calibration/test property.

4.3 Synthetic EPC label #

The latent score is:

Formula / definition
L = 50 + insulation_bonus + glazing_bonus + heating_bonus
    + 8*solar + 4*smart_controls + 5*1(age<=26) + N(0,5)
insulation: Poor -12, Average +8, Good +20
glazing: Single -10, Double +5, Triple +10
heating: old gas -8, modern gas +3, pump +12, resistance -5

Sum the official London 2025 EB1 rating counts. On the 3,000-home pilot, sort latent scores. For each cumulative rating count in order G,F,E,D,C,B, choose the pilot cutoff at index min(2999, round(3000*cumulative_count/total_count)). The six ascending thresholds are recorded in parameters.json: 14.2373884067, 18.5522113097, 28.0040395537, 50.9180391488, 86.3459897315 and 104.0883477129.

Formula / definition
energy_rating = 'GFEDCBA'[bisect_right(cutoffs, L)]

Equality moves to the higher label. This maps a modelled physical ordering to certificate-lodgement marginals. It is not SAP calculation, an actual EPC or evidence of stock-wide rating proportions. energy_rating is not a feature in the baseline snapshot valuation evaluator.

4.4 Synthetic valuation target: no retrofit uplift #

Choose a latent borough uniformly from sorted boroughs with a positive HPI price for the property's type. Equal borough weights are an assumption, not household/transaction weights. Let P_b,t be that borough/type's July 2026 HPI anchor and sigma_p=.18, unchanged from the original price generator:

Formula / definition
raw_price = P_b,t * (A/mu_type)^0.55
            * (1 + 0.02*(b-3))
            * (1.04 if age<=10 else 1)
            * exp(N(-0.5*sigma_p^2, sigma_p))
j_type = public_London_type_HPI_mean / mean(pilot raw_price for that type)
current_value_estimate_gbp = 1000 * round(max(50000, raw_price*j_type)/1000)

Published London type anchors are GBP 1,167,718 Detached, 724,106 Semi-detached, 642,452 Terraced and 424,013 Flat. Pilot intercepts are approximately .760147107, .722832429, .847460528 and .997134979 respectively; exact values are in the report. Intercept normalisation uses public references and the independent pilot, never held-out valuation errors. It does not force the finite final cohort's type means to equal the public means exactly.

No EPC, fabric, heating, controls, solar, retrofit cost, savings or uplift formula enters this target. Noise was not reduced to improve reported MAE. Labels are simulated baseline estimates, not matched observed transaction prices. Latent borough variation is withheld from the unchanged ML inputs, leaving irreducible synthetic uncertainty. The dataset cannot train or establish a causal retrofit-value premium.

5.1 Physical model before monthly allocation #

The energy RNG seed is the big-endian integer from the first eight bytes of SHA256('42:'+property_id), distinct from the property/price seed. 5.2 Seasonal allocation, fuel conversion and PV accounting #

Raw January–December profiles are:

Formula / definition
heat = [.17,.145,.12,.08,.04,.015,.005,.005,.035,.085,.13,.17]
appliances = [.095,.085,.085,.08,.08,.075,.075,.075,.08,.085,.09,.095]
solar = [.025,.04,.075,.10,.125,.135,.135,.115,.09,.065,.035,.025]

Normalise each vector to sum to one. Apply the per-month jitter before normalising heat/appliances; solar has no jitter. Then:

Formula / definition
H_m = k_h*H0*normalised_heat_m
W_m = W/12
B_m = k_e*B0*normalised_appliance_m
V_m = V*normalised_solar_m

gas home:        G_m=(H_m+W_m)/eta; D_m=B_m
pump home:       G_m=0; D_m=B_m+H_m/3+W_m/2.5
resistance home: G_m=0; D_m=B_m+H_m+W_m

S_m=min(D_m, .45*V_m)
I_m=max(0,D_m-S_m)
X_m=V_m-S_m

The implementation first generates six-decimal raw physical monthly values, then rescales heat/base appliances and recomputes fuel/PV balances; this rounding order matters for exact reproduction. PV reduces purchased electricity, not the underlying electrical demand or gas. Export receives no invented revenue.

5.3 Pilot calibration, separate from valuation calibration #

On the disjoint fixed 3,000-home pilot, use 35 bisection iterations within [.1,5] to solve for k_h so median annual purchased gas among gas homes matches London NEED 2024's 10,817.37253845012 kWh. With that heat scale fixed, solve for k_e so median annual grid imports across all pilot homes match 2,466.300000126385 kWh. The electricity calculation respects PV clipping and electric heating. Hot-water demand, COPs, efficiency and behavioural noise are not rescaled to improve valuation accuracy.

Recorded scales: k_h=1.9030779568522123, k_e=1.2586991921489243. The pilot also determines EPC quantiles and price intercepts. No final-cohort valuation errors enter these calculations. Matching two energy medians does not verify variance, tails, heating prevalence, temporal behaviour or joint realism.

5.4 Annual aggregation and fixed benchmark #

Annual H/W/D/V/S fields sum their twelve physical monthly columns. Gas-space and gas-water fields divide annual delivered H/W by applicable eta; electric space/water fields divide them by applicable COP/efficiency. Nonapplicable fuel components are zero. Base appliance electricity equals annual D minus electric space and water components. Purchased annual gas/grid, when loaded by the backend, sum the two-decimal import readings, not six-decimal demand fields. Incomplete fuel coverage yields an unavailable annual import total.

For each new-row benchmark, evaluate a fixed synthetic home of the same type: 100 m2, age 54 (53 during energy year), 3 assumed occupants, average insulation, double glazing, modern gas boiler .90, no PV/controls, London climate .95, behaviour 1, and the v3 scales. Its purchased-energy intensity is:

Formula / definition
benchmark = ((k_h*H0_reference + W_reference)/.90 + k_e*B0_reference)/100

This is a modelled reference, not an official NEED efficiency threshold. Legacy benchmark metadata/values remain unchanged. Renewable share is annual S / annual D (zero when demand is zero). Contribution is none for zero PV generation, otherwise substantial at share>=.20 and limited below. This category concerns electrical PV contribution, not the share of all heat.

12. Leakage controls, model selection and independent calibration #

The original hundred are legacy_diagnostic, excluded from all new model partitions. New customer reservation is independent of targets:

Formula / definition
u = int(first 16 hex digits of SHA256('kew_london_v3:reserve:'+customer_id))/2^64
u < .40 -> fit
.40 <= u < .60 -> selection
.60 <= u < .80 -> calibration
u >= .80 -> test

Actual counts: 803 fit, 334 selection, 381 calibration, 382 test, plus 100 legacy diagnostics. Every property/customer's records share a split. Evaluation validates manifest uniqueness and one-to-one ID/customer joins and rejects customer overlap. There is no chronological evaluation because no observed transaction/snapshot dates exist. New IDs do not reuse exposed v2 rows.

The evaluator uses only floor_area, bedrooms, age, region, property_type, with the existing floor_area_m2 -> floor_area alias. It excludes the target, EPC letter, energy fields, future assessments, derived price proxies, bands and latent borough. Existing preprocessing median-imputes/scales numeric features and one-hot encodes categories with unknown-category handling inside each fitted pipeline. The main numeric inputs are complete, so imputation is not a mechanism for fabricating missing source data. No full-dataset target encoding occurs.

Existing candidates: Ridge(alpha=10) and HistGradientBoosting(max_iter=120, max_leaf_nodes=15, l2_regularization=10, random_state=42, early_stopping=False). Choose boosting only if its selection MAE is <.98 times Ridge selection MAE; otherwise Ridge. The selected candidate is refitted on fit+selection; calibration and test labels remain excluded. Five grouped fit-only folds at sizes 100/250/500/803 provide the learning curve. These curves are development diagnostics conditional on selection; not independent held-out market evidence.

Valuation calibration is distinct from section 5.3's physical pilot. For the 381 independent calibration customers with prediction p_i and target y_i:

Formula / definition
absolute residual r_i = abs(y_i-p_i)
relative residual z_i = r_i/max(50000,p_i)
alpha=.1; n=381
k=ceil((n+1)*(1-alpha))=344
q = sorted residual[k-1]                      # finite-sample order statistic
price-proportional interval: p +/- q_relative*max(50000,p)
constant-width comparator: p +/- q_absolute

The evaluator reports symmetric intervals without clipping negative endpoints. Price-proportional scaling was declared before test evaluation; the comparator is not selected using test coverage. Exchangeability supports marginal synthetic coverage, not guaranteed subgroup coverage, future market coverage or causal effects. The merged London integration now consumes this manifest explicitly through scripts/prepare_london_demo.py: it excludes legacy_diagnostic, trains ml/models/london_snapshot.joblib, and enables the price-proportional interval policy. Existing absolute-interval artifacts retain their behavior. These integration changes are documented separately in the London model review; they do not make the already exposed test cohort fresh again.

14. Reproducibility: commands, fingerprints and evaluation guard #

Use the reviewed reference JSON for offline generation; raw downloads are not required. Python 3.10+ and the standard library suffice for simulation. The recorded byte-identical reproduction used Python 3.10.11; other Python versions can produce small floating-point differences. Existing backend/ML requirements are needed for evaluation/tests; package ranges alone do not fix all versions, so record the runtime and resolved packages when reproducing.

On a genuinely new version/cohort, reserve new customers and freeze choices before a one-time --final evaluation.

15. What a reviewer can and cannot conclude #

Review data lineage, generator assumptions, explicit missingness, label formulas, physical identities, split independence, interval widths and subgroup errors alongside headline scores. The dataset demonstrates a reproducible, internally consistent, public-reference simulation under the unchanged schema. It does not prove current London representativeness, trustworthy observed price labels, real-property EPC accuracy, surveyed retrofit feasibility, real bills/savings, market-calibrated intervals or causal retrofit premiums. Obtaining those claims requires appropriately licensed observed records, verified keys/dates, survey evidence, and a new independent validation design.
